## 一、这个页面在解决什么

这是一份**课程预习成果**：学习京东某 AI 项目时，老师要求用 Agent 做课前预习。该项目要判断「商家宣传」与「商品实际」是否一致，目前出现两类错误：

- **漏放（假阴性）**：参数造假但没踩极限词的商品被放过；
- **误杀（假阳性）**：正常营销话术被误判成欺诈。

所以预习落点不是「商详页有哪些模块」，而是：**页面上哪些组件承载商品信息、AI 该从哪里取证、哪些组件根本不该当证据**。网页以一份真实商详页快照为底，把这条思路做成可点击、可自测的结构。

> 说明：原计划中的「不同品类对比分析」板块已按需求移除，本页只针对一个商品样本做纵深拆解。

## 二、页面能做什么

| 功能 | 说明 |
| --- | --- |
| 连续长页 | 11 张 App 截图裁掉各自重复的状态栏／搜索框／tab／限时立减条／购买栏，再用模板匹配自动去掉 6 处内容重叠，拼成 880 × 12893 的连续长图；外层固定手机框提供唯一一套状态栏、吸顶 tab 和吸底购买栏，滚动时只有内容在动 |
| 27 个可点热区 | **A 类（蓝框）**承载商品信息，展开五层：名称与作用／承载什么信息／可核验性／取证建议／误判风险；**B 类（灰框）**纯功能组件，只给名称＋功能。模块名一律用通用型（商品主图、商品标题、服务承诺栏），具体文案只写在说明正文 |
| 模块清单 | 按页面顺序分组，点任一项可跳到对应位置并展开说明；热区可一键隐藏 |
| 详情图轮播与查看器 | 3 张商品详情图可左右滑动，点击进入按真实界面复刻的全屏查看器（计数、SKU 选择条、价格、加购按钮），可左右切换 |
| 模拟判定 | 4 道题，全部取自页面真实宣传语；判断表达类型（事实／承诺／评价／修辞）并选取证组件，即时反馈对应漏放还是误杀 |
| 页内预习笔记 | 四条结论、两类误判位置、术语表、可核查来源链接 |

## 三、分析框架与核心结论

按「是否结构化 × 是否可证伪」把信息载体分四类，两类错误的位置就清楚了：

|  | 客观 · 可证伪 | 主观 · 修辞 |
| --- | --- | --- |
| **结构化字段** | 规格参数、SKU 属性、能效等级 → 机器可直接比对，**漏放高发（取证通道错配）** | 卖点标签、营销词 → 带结构化外壳的修辞，边界最模糊 |
| **非结构化表达** | 详情图文、资质凭证、吊牌 → 需 OCR 与外部数据源核验，是交叉验证入口 | 营销文案、评价、模特图 → 不可证伪，**误杀高发（语用类型误判）** |

四条结论：

1. **取证通道错配导致漏放**：参数造假落在结构化事实区，审核规则却常盯极限词／绝对化用语。商品一个「最」字没说，容量、能效、型号照样可以造假。
2. **语用类型误判导致误杀**：「Pro 再超前」「景深效果超惊艳」是体验修辞，不可证伪，当成可核验事实就会误伤正常营销。
3. **大量硬参数只存在于图片里**：本页「4800 万像素融合式主摄」「A20 Pro 2 纳米制程」都写在详情长图上，而规格参数表只列到品牌、编号、系统、机型。只取结构化字段或只查文本，这些宣称整体落在取证范围外。
4. **矛盾藏在字段之间**：店铺公告图写「全新未拆封 · 全国联保」，常见问题却写「二手商品的来源是什么」，服务承诺栏同时出现「免费上门退换」与「不支持 7 天无理由退货」。单看每处都不一定违规，交叉比对才露馅。

## 四、文件结构

| 路径 | 作用 |
| --- | --- |
| `index.html` | 单页应用，含全部样式、交互、说明卡与题库；无外部依赖 |
| `assets/page-long.jpg` | 拼接后的连续长页（约 1.6 MB） |
| `assets/gallery-1~3.jpg` | 商品详情图轮播素材 |
| `assets/viewer-ref.jpg` | 图片查看器界面参考图（查看器 UI 按其复刻） |
| `assets/segments.js` / `segments.json` | 各截图段在长图中的坐标，`index.html` 自动读取；改图后热区坐标自动同步 |
| `tools/build.py` | 长图拼接脚本：裁固定栏 → 模板匹配去重叠 → 输出长图与段坐标 |
| `.nojekyll` | 让 GitHub Pages 跳过 Jekyll，避免静态资源被忽略 |

## 五、本地运行与复现

```bash
# 1) 直接看
open index.html                      # 或双击

# 2) 起个本地服务（推荐，避免个别浏览器的 file:// 限制）
python3 -m http.server 8000
# 打开 http://localhost:8000

# 3) 重新生成长图（需 Pillow）
python3 -m pip install Pillow
python3 tools/build.py
```

`tools/build.py` 顶部的 `D`（截图目录，默认 `~/Desktop/京东`）和 `OUT`（输出目录）是本机绝对路径，换机器时改这两处即可。脚本会按预设的浏览顺序读取 11 张截图，自动检测并裁掉相邻重复，输出 `assets/page-long.jpg`、`assets/segments.js`、`assets/segments.json` 与 3 张轮播图——**不需要手动改 `index.html` 里的热区坐标**。

## 六、素材与来源

- 15 张京东 App 实拍截图（11 张商详页 + 3 张详情图 + 1 张图片查看器），采集于 2026-11-05 17:05–17:08，同一设备／账号／地区。
- 样本商品为 iPhone 18 Pro 折叠机，来自**拍拍二手买手店，非京东自营**；店铺自行发布的公告与平台结构化字段混在同一屏，这正是取证前需要先分层的原因。
- 京东 2025 年报仅披露两大类商品收入（电子产品及家用电器 6051 亿元、日用百货 4187 亿元），**不存在「GMV 前三品类」的官方口径**，因此页面不做品类规模对比。

可核查来源：

- [京东开放平台 · 商品发布接口](https://jos.jd.com/commondoc?listId=436) —— 不同类目必填属性不同，必填项以 `true` 标识
- [京东全球购开放平台 · 商品信息规范总则](https://jdw-rule.jd.hk/detail?ruleId=1317754600069242880) —— 类目、品牌、标题、视觉规范、商品属性、SPU/SKU、价格、发货、售后
- [京东商家帮助中心 · 类目资质说明](https://helpcenter.jd.com/vender/issue/1000-45466.html) —— 发布商品环节触发的类目资质校验
- [京东 2025 年报点评（分品类收入）](https://m.gelonghui.com/news/5182616)

规范类来源为全球购版总则与开放平台接口，国内版同名规范字段框架共通、未逐条复核；截图内容以页面实际呈现为准，不作为京东官方规则表述。
